Learning objectives

By the end of this module you should be able to:

  • Explain why R can complement a graphical GIS such as QGIS.
  • Identify the roles of terra and sf in the geospatial R ecosystem.
  • Create an organized RStudio project with relative file paths.
  • Apply consistent file naming, script organization and documentation practices.

1.1 · Principle and scope

GIS operations commonly performed through the QGIS graphical interface can also be expressed as R commands. An R script captures the sequence of steps so it can be inspected, modified and repeated. This course is intended as a programming-based complement to introductory GIS teaching, not as a replacement for understanding GIS concepts.

From QGIS to R: A vector overlay or raster crop might be performed using GUI tools in QGIS. In R, the corresponding workflow is written as code that can be rerun when the input data or study area changes.

1.2 · The R geospatial ecosystem

R includes many packages for manipulating geospatial information. The source course focuses mainly on terra for vector and raster processing, and identifies sf as another essential vector-oriented package.

terra

Spatial data handling and operations using SpatVector and SpatRaster objects.

sf

Vector features, their geometries, coordinate reference systems and attributes.

RStudio

An integrated development environment for writing, running and organizing R scripts and projects.

Install packages once if they are not yet available, then load them at the beginning of a new R session:

# Run once if needed (uncomment the next line):
# install.packages(c("terra", "sf"))

library(terra)
library(sf)

1.3 · Organize your workspace: one session, one project

The source lesson emphasizes a simple rule: one session = one directory = one RStudio project. Create a clearly named project folder and keep raw data separate from scripts and outputs. The .Rproj file anchors the project and supports relative paths.

my_project/
├── my_project.Rproj
├── data/ ← original datasets (do not edit)
├── scripts/ ← R analysis scripts
│   ├── functions/ ← reusable functions
│   └── 01_getting_started.R
├── outputs/ ← figures, tables, derived data
└── documents/ ← exercise briefs and reports

Recommended workflow: read raw datasets from data/ → execute code from scripts/ → write results to outputs/. For example, use "data/countries.gpkg" instead of an absolute path tied to one computer.

1.4 · Use simple, unambiguous names

The course recommends lower-case names without spaces or accents, using underscores to separate words. Choose names that describe the task or dataset.

Recommended

session_02_rasters/
01_import_vectors.R
soil_samples.csv

Avoid

nouveau PRojet 4/
Mon Analyse.R
données été.csv

1.5 · Organize tasks by scripts

Keep one task or exercise in one .R script. Add comments with # to explain each step; save frequently. In RStudio, Run executes a selected line or selection, whereas Source executes the full script.

Try this project setup script (it does not overwrite existing data):

# Create project folders if missing
folders <- c("data", "scripts", "outputs", "documents")
for (folder in folders) {
  dir.create(folder, showWarnings = FALSE)
}
dir.create("scripts/functions", showWarnings = FALSE)

# Check the project's current working directory
getwd()

# List its contents
list.files()

1.7 · Working with spatial data

Original course datasets are now available: Explore the real vector data collection and download the accompanying R script. The synthetic dataset below remains an optional introductory illustration.

Optional synthetic demonstration

As a bridge to Module 2, you can work with a small synthetic set of six point locations. These are illustrative teaching points, not observed field measurements and not datasets supplied with the source course.

Files to download: sample_sites.geojson (point geometries), sample_sites.csv (attribute table), and 01-example-data.R (guided R example). For local RStudio work, download or clone the whole repository to preserve the relative file paths.
library(terra)

# Read a point layer in GeoJSON format
sites <- vect("data/vectors/sample_sites.geojson")

# Inspect its coordinate reference system
crs(sites)

# Make a basic map
plot(sites, main = "Synthetic sample sites")

# Write a derived output without editing raw data
dir.create("outputs", showWarnings = FALSE)
writeVector(sites, "outputs/sample_sites_copy.gpkg", overwrite = TRUE)

Mini exercise: Run the example from your project's root folder. Compare the GeoJSON attribute table with the CSV file. Explain why the original dataset is kept in data/ while the exported GeoPackage is written to outputs/.

Key takeaways

  • R makes geospatial analysis repeatable through scripts.
  • terra covers both rasters and vectors; sf is particularly important for vector data.
  • Keep raw inputs, scripts and outputs separate.
  • Use clear names, comments and relative file paths.
